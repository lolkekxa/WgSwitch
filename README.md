# WgSwitch

Пульт для личного WireGuard-туннеля под Windows. Сам VPN не реализует: включает и выключает
службу туннеля через официальный клиент WireGuard и показывает её состояние.

## Что установить заранее

1. **WireGuard для Windows**: https://www.wireguard.com/install/ (нужны `wireguard.exe` и `wg.exe` в `C:\Program Files\WireGuard`).
2. **.NET 8 Desktop Runtime** (x64): https://dotnet.microsoft.com/download/dotnet/8.0. Не нужен для self-contained сборки.
3. Для сборки: .NET SDK 8 или новее.

## Первый запуск

Если серверов ещё нет, вместо пульта открывается мастер из трёх шагов:

1. Проверка, что WireGuard установлен (со ссылкой на установку; статус обновляется сам).
2. Адрес сервера, его публичный ключ, имя туннеля и ваш IP в VPN. WgSwitch генерирует пару ключей через `wg.exe`
   и пишет `C:\ProgramData\WgSwitch\<имя>.conf`. Папка закрыта: доступ только у Администраторов и SYSTEM.
3. Блок `[Peer]` с вашим публичным ключом, который нужно добавить на сервер (кнопка «Скопировать»).

Уже есть свой `.conf`: «У меня есть .conf» на первом шаге.

## Несколько серверов

Настройки → «+ Добавить» открывает тот же мастер. На главном экране появляются капсулы серверов
с точкой состояния. Кнопка включает и выключает выбранный сервер. Включённым можно держать
несколько туннелей сразу, если у серверов разные подсети: мастер сам предлагает следующую свободную
(`10.8.0.x`, затем `10.9.0.x`, …). В меню трея — пункт на каждый сервер. Иконка красная, если хоть один
включённый сервер не отвечает, и зелёная, если что-то подключено.

«Удалить» в настройках убирает сервер из списка, но не удаляет его `.conf`. Включённый туннель сначала нужно выключить.

Переименовать сервер: Настройки → поле «Имя». WgSwitch сам переименует `.conf` и поправит путь
(имя туннеля в Windows — это имя файла). Переименовывать файл вручную не нужно: путь в настройках
останется старым. Как и удаление, работает только при выключенном туннеле.

Что сделать на сервере, чтобы он был доступен только при включённом VPN: [SERVER.md](SERVER.md).

## Резервная копия

Настройки → «Резервная копия» → «Экспорт» сохраняет в один файл `.wgsb` все серверы, их IP для пинга
и сами конфиги **вместе с приватными ключами**. Файл зашифрован паролем (AES-256-GCM, ключ из пароля
через PBKDF2-SHA256, 600 000 итераций), поэтому его можно хранить в облаке. Пароль восстановить нельзя.

Восстановить: «Импорт» в настройках или «Есть резервная копия? Восстановить» на первом шаге мастера
(на новом компьютере вы начнёте именно с него). Конфиги ложатся в `C:\ProgramData\WgSwitch`, серверы
с теми же именами заменяются, остальные остаются. Отличающийся конфиг на диске не затирается, а
переименовывается в `.bak`.

Приватные ключи приложение читает только в этот момент, держит их в памяти до шифрования и нигде
не сохраняет в открытом виде.

## Свой wg0.conf вручную

Укажите путь в настройках (шестерёнка). В конфиге лежит приватный ключ, поэтому закройте папку
от обычных пользователей (в PowerShell от администратора):

```powershell
New-Item -ItemType Directory -Force C:\ProgramData\WgSwitch | Out-Null
Copy-Item .\wg0.conf C:\ProgramData\WgSwitchicacls C:\ProgramData\WgSwitch /inheritance:r /grant:r "*S-1-5-32-544:(OI)(CI)F" "*S-1-5-18:(OI)(CI)F"
```

Имя файла становится именем туннеля (`wg0.conf` → `wg0` → служба `WireGuardTunnel$wg0`).
Допустимы латиница, цифры и `_=+.-`, до 32 символов.

## Сборка

Каждый пуш в `main` собирается на GitHub Actions (`.github/workflows/build.yml`): готовый `WgSwitch.exe`
лежит в артефактах запуска. Тег вида `v1.0.0` дополнительно создаёт релиз с exe.

Локально:

```powershell
# обычная сборка
dotnet build -c Release

# один файл (~0.5 МБ), нужен .NET 8 Desktop Runtime
dotnet publish -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -o publish

# один файл без зависимостей (~65 МБ), runtime внутри
dotnet publish -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:EnableCompressionInSingleFile=true -o publish-sc
```

`PublishTrimmed` для этого проекта недоступен: SDK запрещает trimming для WPF и WinForms
(ошибки NETSDK1168 и NETSDK1175).

## Как работает

| Действие  | Команда |
|-----------|---------|
| Включить  | `wireguard.exe /installtunnelservice "<путь к .conf>"` |
| Выключить | `wireguard.exe /uninstalltunnelservice <имя>` |
| Состояние | служба `WireGuardTunnel$<имя>` (SCM), затем пинг до IP из настроек |
| Handshake / трафик | `wg.exe show <имя> latest-handshakes` и `wg.exe show <имя> transfer` |

Настройки хранятся в `%APPDATA%\WgSwitch\settings.json`: список серверов (путь к конфигу и IP для пинга), выбранный сервер и флаги. Ключи туда не попадают.
Старый формат с одним сервером переносится в список автоматически.
Приватный ключ существует только в wg0.conf: мастер получает его от `wg genkey`, держит в памяти до записи файла и нигде не логирует.
Автозапуск — задача планировщика `WgSwitch` («при входе», наивысшие права).

## Структура

```
App.xaml(.cs)              запуск, одна копия (Mutex), трей, показ/уничтожение окна
MainWindow.xaml(.cs)       окно: кнопка, статус, карточка, настройки, мастер первого запуска
Ui.cs                      скруглённый клип для капсул
Models/TunnelStatus.cs     состояние туннеля
Services/WireGuardService  install/uninstall, опрос службы, пинг, wg show
Services/TrayService       NotifyIcon, иконки трёх цветов (рисуются в рантайме), тёмное меню
Services/SettingsService   settings.json, автозапуск
Services/ConfigFactory     мастер: проверка ввода, ключи через wg.exe, wg0.conf в закрытой папке
Services/BackupService     зашифрованная резервная копия серверов и конфигов (.wgsb)
Services/Native            DWM, SCM, сброс рабочего набора
Services/Proc              запуск внешних утилит без окна
Assets/                    шрифты Geist (OFL), иконка приложения
```
