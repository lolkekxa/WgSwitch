# Сервер: доступ только через VPN

Цель: админка сервера (SSH, панели, базы) отвечает только на адрес `10.8.0.1` внутри туннеля.
Снаружи открыты только UDP-порт WireGuard и то, что должно быть публичным: сайты и порт вашего
основного VPN. Выключили туннель в WgSwitch — админка для вас (и для всех остальных) закрыта.

Команды для Ubuntu/Debian. Всё выполняется от root (`sudo -i`).

> **Не закройте себе дверь.** Пока не проверите SSH через туннель (шаг 5), не удаляйте
> публичное правило для SSH. Держите под рукой веб-консоль хостера (VNC/KVM): она работает,
> даже если файрвол настроен неправильно.

## 0. Если на сервере уже есть сайты и VPN

Прятать за туннель нужно **только админку**: SSH, панели (3x-ui, Marzban, wg-easy UI, Portainer),
базы, служебные порты. То, чем пользуются другие люди или ваши устройства, остаётся публичным:

| Что | Куда |
|-----|------|
| Сайты (80, 443) | публично |
| Порт вашего VPN (Xray/VLESS, Outline, OpenVPN, AmneziaWG, wg-easy…) | публично |
| SSH, веб-панели, БД, Portainer, метрики | только через туннель |

Сначала посмотрите, что сейчас слушает сервер и какой файрвол уже стоит:

```bash
ss -tulpn                      # все открытые порты и процессы
wg show 2>/dev/null; ip -br a  # есть ли уже WireGuard и какие интерфейсы/подсети заняты
docker ps --format '{{.Names}}\t{{.Ports}}' 2>/dev/null
ufw status 2>/dev/null; nft list ruleset 2>/dev/null | head -50
```

**Если ваш VPN тоже на WireGuard**, проверьте, не занято ли то, что использует этот гайд:
интерфейс `wg0`, порт `51820/udp`, подсеть `10.8.0.0/24`. Именно эти значения по умолчанию у **wg-easy**.
Есть два варианта:

- **Проще: стать клиентом существующего VPN.** Создайте в нём ещё одного клиента (в wg-easy это кнопка
  в веб-интерфейсе), скачайте `.conf` и в WgSwitch выберите «У меня есть .conf». В настройках укажите
  IP сервера внутри этого VPN (у wg-easy это `10.8.0.1`). Шаги 1–2 и 7 ниже тогда не нужны, сразу переходите к файрволу.
- **Отдельный туннель для админки.** Везде ниже замените `wg0` → `wg1`, `51820` → `51830`,
  `10.8.0.` → `10.9.0.`. В мастере WgSwitch укажите адрес `сервер:51830` и свой IP `10.9.0.2`.

**Если в Windows уже работает другой VPN на весь трафик**, в мастере WgSwitch **не ставьте**
«Весь интернет через VPN». Два туннеля, которые оба забирают `0.0.0.0/0`, мешают друг другу.
Без этой галочки WgSwitch ведёт через себя только подсеть `10.8.0.0/24`, и VPN друг другу не мешают.

## 1. WireGuard и ключ сервера

```bash
apt update && apt install -y wireguard
cd /etc/wireguard && umask 077
wg genkey | tee server.key | wg pubkey > server.pub
cat server.pub        # этот ключ вставить в WgSwitch, шаг 2 «Публичный ключ сервера»
```

## 2. Конфиг сервера

Пройдите мастер в WgSwitch до шага 3: он покажет блок `[Peer]` с вашим ключом.
Создайте `/etc/wireguard/wg0.conf`:

```ini
[Interface]
Address = 10.8.0.1/24
ListenPort = 51820
# приватный ключ читается из файла и не попадает в конфиг
PostUp = wg set %i private-key /etc/wireguard/server.key

# ↓ блок из WgSwitch (шаг 3)
[Peer]
PublicKey = <ключ из WgSwitch>
AllowedIPs = 10.8.0.2/32
```

```bash
chmod 600 /etc/wireguard/wg0.conf
systemctl enable --now wg-quick@wg0
wg show               # интерфейс wg0, listening port 51820
```

## 3. Файрвол: наружу только публичное

Если на сервере уже настроен другой файрвол (свои правила `iptables`/`nftables`, скрипты панели VPN),
**не ставьте ufw поверх**: добавьте те же правила в свою систему. Ниже вариант для ufw.

```bash
apt install -y ufw
ufw default deny incoming
ufw default allow outgoing

ufw allow 51820/udp            # туннель WgSwitch
ufw allow in on wg0            # всё, что пришло через туннель, разрешено
ufw allow OpenSSH              # ВРЕМЕННО, пока не проверим SSH через VPN

# ↓ всё, что должно остаться публичным (по выводу ss -tulpn из шага 0)
ufw allow 80,443/tcp           # сайты
ufw allow 443/udp              # HTTP/3, если включён
# ufw allow <порт вашего VPN>/tcp или /udp

ufw enable
ufw status verbose
```

Если хотите пускать из туннеля не всё, а выборочно, замените `ufw allow in on wg0` на
`ufw allow in on wg0 to any port 22 proto tcp` (и так далее для каждого порта).

**Ваш VPN может перестать выпускать клиентов в интернет.** По умолчанию ufw блокирует
пересылку пакетов между интерфейсами. Если ваш VPN работает не в Docker (wg-quick, OpenVPN, AmneziaWG
в systemd) и клиенты после `ufw enable` «подключены, но интернета нет», разрешите им выход:

```bash
ip route | grep default                      # внешний интерфейс, например eth0
ufw route allow in on <интерфейс VPN> out on eth0
```

Чтобы проверить, не задело ли что-то, сразу после `ufw enable` откройте сайты и подключитесь
своим VPN с телефона.

## 4. Подключитесь из Windows

В WgSwitch нажмите кнопку. Должно стать «Подключено», пинг в миллисекундах, свежий handshake.
На сервере `wg show` покажет `latest handshake` и трафик для вашего пира.

## 5. Проверьте SSH через туннель и закройте публичный

С Windows, **при включённом VPN**:

```powershell
ssh user@10.8.0.1
```

Получилось — закрываем SSH снаружи:

```bash
ufw delete allow OpenSSH
ufw status
```

Теперь `ssh user@<публичный IP>` перестанет отвечать, а `ssh user@10.8.0.1` будет работать только с включённым VPN.

## 6. Админ-панели: открыть только из туннеля

**Не привязывайте nginx к `10.8.0.1`** (`listen 10.8.0.1:...`). Этот адрес существует, только пока
поднят `wg0`. Если при загрузке nginx стартует раньше туннеля или туннель перезапустят, nginx
не запустится целиком, и вместе с панелью упадут **все публичные сайты**.

Надёжнее так: панель слушает отдельный порт на всех интерфейсах, ufw этот порт снаружи не
открывает (а `ufw allow in on wg0` из шага 3 пускает его из туннеля), и nginx дополнительно
проверяет адрес клиента. Пример для сервиса на `127.0.0.1:8081`:

```nginx
# /etc/nginx/sites-available/vpn-admin
server {
    listen 8800;
    allow 10.8.0.0/24;
    deny all;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
```

```bash
ln -s /etc/nginx/sites-available/vpn-admin /etc/nginx/sites-enabled/
nginx -t && systemctl reload nginx
```

Открывать с включённым VPN: `http://10.8.0.1:8800`. HTTPS не нужен, трафик и так зашифрован туннелем.

Базы (PostgreSQL, Redis) оставьте на `127.0.0.1`. С компьютера к ним удобно ходить через SSH по VPN:
`ssh -L 5432:127.0.0.1:5432 root@10.8.0.1`, затем подключаться к `localhost:5432`.

**Docker обходит ufw.** Порт, опубликованный как `-p 8080:80`, доступен из интернета, что бы ни
говорил `ufw status`. Это работает в обе стороны:
- сайты и VPN в Docker продолжат работать после `ufw enable` (это хорошо);
- панели в Docker (3x-ui, Marzban, wg-easy UI на `51821`, Portainer) **останутся открытыми всему миру**,
  если опубликованы как `0.0.0.0:порт`. Опубликуйте их на `127.0.0.1:порт:порт` и откройте через nginx, как выше.
  Проверка: `docker ps` не должен показывать `0.0.0.0:<порт панели>`.

Исключение — контейнеры с `network_mode: host`: у них нет проброса портов, их закрывает обычный ufw.

**Админка на публичном домене** (`https://ваш-домен/admin`, поддомен с Adminer или консолью MinIO):
`allow 10.8.0.0/24; deny all;` в таком `location` не сработает. Без галочки «весь интернет через VPN»
запрос на публичный домен идёт **мимо туннеля**, с вашего обычного IP, и получит 403. Поэтому
публичный вход в админку уберите из конфигов nginx, а саму админку откройте на отдельном порту, как выше.

## 7. (Опционально) весь интернет через VPN

Нужно, только если в мастере включили «Весь интернет через VPN».

```bash
echo 'net.ipv4.ip_forward=1' > /etc/sysctl.d/99-wireguard.conf && sysctl --system
ip route | grep default        # имя внешнего интерфейса, например eth0 или ens3
```

Добавьте в `[Interface]` серверного `wg0.conf` (вместо `eth0` ваш интерфейс):

```ini
PostUp   = iptables -t nat -A POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE
PostDown = iptables -t nat -D POSTROUTING -s 10.8.0.0/24 -o eth0 -j MASQUERADE
```

```bash
ufw route allow in on wg0 out on eth0
systemctl restart wg-quick@wg0
```

## Проверка снаружи

С любой машины **без** VPN:

```bash
nmap -Pn <публичный IP>              # TCP: всё filtered, SSH не виден
nmap -Pn -sU -p 51820 <публичный IP> # open|filtered — это нормально, WireGuard молчит на чужие пакеты
```

## Второй сервер

В WgSwitch: Настройки → «+ Добавить». Мастер сам предложит свободное имя и **другую подсеть**
(второй сервер — `10.9.0.x`, третий — `10.10.0.x`). Подсети должны различаться: тогда оба туннеля
можно держать включёнными одновременно, и пакеты не перепутаются.

На втором сервере всё то же самое, что выше, только с его подсетью. На шаге 3 мастер покажет
нужную строку `Address` для его `[Interface]`, например:

```ini
[Interface]
Address = 10.9.0.1/24
ListenPort = 51820
PostUp = wg set %i private-key /etc/wireguard/server.key

[Peer]
PublicKey = <ключ из WgSwitch для этого сервера>
AllowedIPs = 10.9.0.2/32
```

В файрволе и в nginx второго сервера замените `10.8.0.` на `10.9.0.`. Ключи у каждого сервера свои:
мастер генерирует новую пару для каждого.

## Ещё одно устройство

Пройдите мастер WgSwitch на втором компьютере с IP `10.8.0.3`, допишите его `[Peer]` в серверный
`wg0.conf` и примените без разрыва текущих подключений:

```bash
bash -c 'wg syncconf wg0 <(wg-quick strip wg0)'
```

## Если что-то не так

| Симптом | Что проверить |
|---------|---------------|
| «Нет ответа от сервера», handshake пустой | Открыт ли `51820/udp` в ufw **и** в панели хостера (облачный файрвол / security group); верный ли адрес и ключ сервера |
| Handshake есть, пинга нет | `AllowedIPs` пира на сервере = ваш IP (`10.8.0.2/32`); `ufw allow in on wg0` |
| Потеряли доступ по SSH | Веб-консоль хостера → `ufw allow OpenSSH` |
| Сервис доступен снаружи | `ss -tlnp` — он слушает `0.0.0.0`? Привяжите к `10.8.0.1`; Docker — порты с IP |
